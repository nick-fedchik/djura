# AUDIT EXECUTION RULES (для всіх `AUDIT-*.md` у цьому каталозі)

Адаптовано з `~/vida/docs/audit/AUDIT-RULES.md` до розміру та стеку цього проєкту (Godot 4.7, GDScript, Python-інструменти).

## 1. Незалежність і безпека репозиторію

1. **Лише читання.** Аудитор не редагує код, ресурси й тести. Пише тільки у `docs/audit/`. Патчі перевіряються в копії або як diff у додатку.
2. **Фіксація бази.** У шапці кожного протоколу: короткий коміт `HEAD`, кількість незакомічених записів `git status --short`. У цьому дереві працює кілька агентів, тож номери рядків прив'язані до зазначеного коміту.
3. **Тести запускаються лише через `tools/run_tests.sh` або окремим `godot --headless --path . -s res://test/<файл>.gd` із таймаутом** (див. `CLAUDE.md`, розділ про сторожовий таймер). Якщо команда змінила відстежуваний файл, його відновлюють `git checkout -- <файл>` і це вказують у розділі меж.
4. **Не створювати ADR/SHR/SWR/TASK.** Їх виводить власник із протоколів. Рядки з пропозицією нових вимог оформлюються як EARS-речення в самому протоколі.
5. **Жодних мережевих дій** під час аудиту (Ollama на `192.168.68.68`, Meshy, Blender-рендер не запускаються).

## 2. Стандарт доказів

1. Кожен дефект має ID, серйозність (CRITICAL / HIGH / MEDIUM / LOW), `файл:рядок` на зафіксованому коміті, відтворюваний вектор (команда або grep) і виміряний результат. Гіпотеза, яку перевірили й не підтвердили, пишеться як «не підтверджено» з описом спроби.
2. **Вимірювати, а не стверджувати.** Розміри, лічильники й часи супроводжуються командою.
3. **Завжди вказувати, що в порядку.** Протокол лише з недоліками недостовірний.
4. **Розділ «Межі валідності» обов'язковий.**

## 4. Формат протоколу

Українською. Розділи: шапка (дата, аудитор, об'єкт, коміт, інструменти, зміни в репозиторії), підсумок, що в порядку, реєстр дефектів, пропозиції (EARS з критерієм приймання), план хвилями, межі валідності. Завершені протоколи переносять у `done/` і вносять до `AUDIT-REGISTRY.md`.
