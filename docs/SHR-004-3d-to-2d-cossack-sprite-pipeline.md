# SHR-004: 3D->2D Анімаційний Конвеєр та Спрайтова Графіка («Джура: початок шляху козака»)

- **Статус:** APPROVED
- **Дата:** 2026-10-25
- **Походження:** Власник проєкту («Маємо ноутбук AORUS 5 (RTX 3070) та Jetson 64GB обидва з Ubuntu. Blender можна встановити. Як цими засобами генерувати 3D->2D анімаційні спрайти для гри Джура засобами Antigravity?»)
- **Трасується до:** [`SHR-001`](SHR-001-game-rules-as-verifiable-invariants.md) I-3, I-4, I-6, [`docs/MEMO_FOLKLORE_CHARACTERS.md`](MEMO_FOLKLORE_CHARACTERS.md)

## 1. Потреба (Business Need)
Гра для дітей 8+ «Джура: початок шляху козака» потребує плавної, виразної, сучасної мультиплікаційної 2D-графіки рівня 2026 року, що зберігає дух золотого канону української анімації («Київнаукфільм», художники Едуард Кирич, Володимир Дахно, Давид Черкаський). 

Ручне покадрове малювання сотень фаз рухів для 20+ персонажів вимагає місяців праці художників. Використання наявного домашнього апаратного кластера (ноутбук AORUS 5 з GPU NVIDIA RTX 3070 8GB VRAM та обчислювальний вузол Jetson AGX Orin 64GB) під керуванням Antigravity дозволяє створити повністю автономний конвеєр перетворення 3D-моделей у 2D-спрайт-листи з целулоїдною стилізацією (Cel-Shading), козацькою кінематикою (Бойовий Гопак) та візуальним аудитом якості на базі локального Vision AI (VLM).

---

## 2. Вимоги зацікавленої сторони (Stakeholder Requirements)

| № | Вимога | Опис |
|---|---|---|
| **B-1** | **Повторюваність та повна автоматизація (Headless CLI)** | Конвеєр генерації та рендерингу виконується суто з командного рядка (`blender -b -P tools/render_sprites_3d.py`) без потреби ручного налаштування в GUI. Будь-який персонаж (.glb / .blend) опрацьовується однаковим скриптом з ідентичним художнім стилем. |
| **B-2** | **Автентична стилізація «Київнаукфільм»** | 3D-модель не повинна виглядати як комп'ютерний 3D-пластик (Uncanny Valley). Обов'язкові: плаский целулоїдний шейдинг (ColorRamp: Constant, 2–3 тони освітлення), теплий чорнильний контур кольору темної туші (Inverted Hull / Line Art) та яскраві народні кольори. |
| **B-3** | **Апаратне прискорення контуру на GPU (Заборона повільного CPU Freestyle)** | Контурний пас рендериться безпосередньо ядрами RTX 3070 в рушії EEVEE Next (Inverted Hull / GPU Line Art), рендер 8–12 кадрів спрайту займає не більше 3 секунд замість хвилинного очікування на CPU. |
| **B-4** | **Автентична кінематика Бойового Гопака** | Специфічні козацькі рухи («Тинок», «Щупак 180°», «Повзунець», ширяння на киреї) не замінюються шаблонними бійками з Mixamo/карате, а описуються процедурною кінематикою та ключовими кадрами в Blender із дотриманням мультяшного розтягування (Squash & Stretch). |
| **B-5** | **Фіксація точки опори (Origin Pivot Invariant)** | Точка контакту ніг із землею на всіх кадрах і всіх анімаціях суворо прив'язана до $Z = 0$ (низ центру спрайту), щоб унеможливити провалювання персонажа під платформу або тремтіння при зміні анімацій у Godot. |
| **B-6** | **Попперівський візуальний аудит якості на Jetson 64GB (VLM)** | Мультимодальна нейромережа на Jetson (`gemma4:12b` / `gemma3:12b` через Ollama) виконує функцію Popperian Red Teamer: аналізує згенеровані кадри на відсутність артефактів геометрії, правильність силуету (оселедець, пухкі щоки, ніс-ґудзик) та відповідність емоцій дитячому віку (Zero-Horror). |
| **B-7** | **Безшовна інтеграція в Godot 4 Web та Xbox Series X** | Сгенеровані спрайт-листи автоматично пакуються у формат `.png` з прозорим альфа-каналом та супроводжуються файлом ресурсу `SpriteFrames` (`.tres`) для Godot 4; повна сумісність із WebGL 2.0 та 60 FPS на консолі. |
| **B-8** | **Ліцензійна чистота** | Усі моделі, текстури та анімації мають бути ліцензійно чистими для публічного поширення (відкриті ваги, відсутність обмежувальних підписок). |

## 3. Ризики та заходи зниження

1. **Ризик OOM (переповнення пам'яті) при генерації важких 3D моделей:**
   * *Опис:* Локальні моделі типу TRELLIS або Hunyuan3D-2 потребують 12–16 ГБ VRAM, що перевищує 8 ГБ RTX 3070 на ноутбуку.
   * *Захід:* Важкі генеративні моделі запускати на Jetson J501 (де доступно 64 ГБ спільної LPDDR5 пам'яті), або для початкових моделей використовувати відкритий експорт онлайн-генераторів, рендерячи їх локально на RTX 3070.
2. **Ризик неприродної пластмасовості рухів (Uncanny Motion):**
   * *Опис:* Лінійне інтерполювання кісток у 3D виглядає механічно.
   * *Захід:* Застосування принципу "On Twos" (анімація через кадр на 12–15 fps всередині 60 fps гри) та кривих сплайнів Bezier із різким прискоренням і повільним входом (Ease-in / Ease-out).
3. **Ризик зміни масштабу між різними персонажами:**
   * *Опис:* AI-генератори віддають меші випадкового розміру.
   * *Захід:* Нормалізація висоти моделей за еталонною коробкою (Bounding Box) у Blender-скрипті перед початком рендерингу (Джура = 1.0, Чортик = 0.75, Опричник = 1.25).
