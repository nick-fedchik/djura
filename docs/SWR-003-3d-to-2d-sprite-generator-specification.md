# SWR-003: Специфікація програмних вимог до 3D->2D конвеєра та спрайтової інтеграції

- **Статус:** APPROVED
- **Дата:** 2026-10-25
- **Трасується до:** [`SHR-004`](SHR-004-3d-to-2d-cossack-sprite-pipeline.md), [`ADR-003`](ADR-003-3d-to-2d-sprite-pipeline-architecture.md)

---

## 1. Загальний огляд
Цей документ визначає технічні вимоги та критерії приймання для автоматизованого конвеєра експорту 3D-моделей у 2D-анімаційні спрайт-листи для гри «Джура: початок шляху козака» на базі Blender Headless CLI, апаратного рендерера EEVEE Next (RTX 3070) та візуального аудитора якості Jetson Orin 64GB (VLM).

---

## 2. Програмні вимоги (Software Requirements)

### SWR-003-01: Консольний інтерфейс утиліти `tools/render_sprites_3d.py`
Утиліта повинна виконуватися через інтерпретатор Blender у безвіконному режимі:
```bash
blender -b -P tools/render_sprites_3d.py -- [ПАРАМЕТРИ]
```
**Параметри командного рядка:**
* `--model <path>`: Шлях до файлу 3D-моделі (`.glb`, `.gltf` або `.blend`).
* `--anim <name>`: Назва анімаційного треку (`idle`, `run`, `jump`, `hopak_tynok`, `hopak_shchupak`, `hopak_povzunets`, `fall`, `bonk`).
* `--frames <int>`: Кількість кадрів для рендерингу (за замовчуванням: 8).
* `--resolution <int>`: Розмір сторони квадратного кадру в пікселях (за замовчуванням: 256).
* `--fps <int>`: Базова частота анімації для гри (за замовчуванням: 12).
* `--out <path>`: Шлях до результуючого файлу спрайт-листа (`.png`).
* `--tres-out <path>`: Шлях до згенерованого ресурсу Godot 4 `SpriteFrames` (`.tres`).

*Критерій приймання:* Скрипт виконується без помилок, повертає exit code 0 і створює цільові файли PNG та TRES.

---

### SWR-003-02: Налаштування камери, сцени та вирівнювання півота (Origin Pivot)
1. **Камера:** Ортографічна (`type = 'ORTHO'`), кут нахилу до горизонту 0° (суворий 2D-профіль для платформера).
2. **Прозорість:** Фон рендеру прозорий (`film_transparent = True`, колірне кодування `RGBA`).
3. **Нормалізація півота (Z=0 Invariant):**
   * Нижня точка мешу (контакт підошов взуття в стані спокою) повинна суворо відповідати координаті $Z = 0$ у світі Blender.
   * У згенерованому кадрі 256×256 піксель $X = 128, Y = 236$ є постійною точкою контакту з землею (константний нижній відступ 20 пікселів для тіней та змахів).

*Критерій приймання:* Кадри різних анімацій одного персонажа мають ідентичну висоту горизонту опори ніг; при перемиканні анімацій у Godot персонаж не підстрибує і не провалюється крізь колізію платформ.

---

### SWR-003-03: Матеріал целулоїдного шейдингу (Toon Shading) та GPU Inverted Hull контур
1. **Матеріал:**
   * Дерево шейдера генерує ступінчасте затінення через вузол `Shader to RGB` → `ColorRamp` (тип `CONSTANT` з 3 сегментами: Базовий колір 100%, Тінь 65%, Блік 115%).
2. **Контур Inverted Hull (GPU-прискорений):**
   * На меш додається модифікатор `Solidify` (Normal Flip, Material Offset = 1).
   * Матеріал контуру: `Emission` чистого колірного відтінку української туші (`RGB: 0.18, 0.08, 0.05`), товщина контуру 1.5–2 пікселі на проекції.
   * **Сувора заборона CPU Freestyle** для запобігання затримкам рендерингу.

*Критерій приймання:* Час рендерингу 8 кадрів 256×256 на GPU RTX 3070 не перевищує 3.0 секунд.

### SWR-003-04: Процедурний генератор поз Бойового Гопака (`tools/cossack_poses.py`)
Якщо вхідний .glb файл містить скелет (Rigify або стандартний Humanoid Biped), але не має специфічних козацьких анімацій, модуль процедурно виставляє ключові кадри обертання кісток (IK / FK):
1. **`hopak_tynok` (8 кадрів):** виніс правого коліна вгору, різкий козацький прямий удар стопою з відтяжкою носка вгору.
2. **`hopak_shchupak` (10 кадрів):** високий стрибок, горизонтальний шпагат 180° у повітрі з доторком рук до носків чобіт.
3. **`hopak_povzunets` (8 кадрів):** низький присід навпочіпки з поперемінним викиданням прямих ніг вперед над землею.
4. **`kyreya_glide` (6 кадрів):** розгортання крил-киреї в польоті з хвильовим коливанням тканини.

*Критерій приймання:* Кістки не ламаються в суглобах, кути обмежені анатомічними межами, деформації сітки плавні.

---

### SWR-003-05: Збірка текстурного атласу та ресурсу Godot 4 `SpriteFrames`
1. Після рендерингу окремих кадрів `frame_000.png .. frame_NNN.png` скрипт компонує їх у горизонтальний спрайт-аркуш `sprite_sheet.png`.
2. Автоматично створюється файл `sprite_frames.tres` формату Godot 4:
   * Тип: `SpriteFrames`.
   * Анімація з відповідною назвою (`run`, `jump` тощо).
   * Правильно розбиті `AtlasTexture` з координатами `region = Rect2(i * 256, 0, 256, 256)`.
   * Встановлено `speed = 12.0` fps та `loop = true/false` за типом анімації.

*Критерій приймання:* Файл `.tres` без помилок відкривається в Godot 4, вузол `AnimatedSprite2D` програє анімацію на 12 FPS.

### SWR-003-06: Стилістичний валідатор якості Jetson VLM (`tools/vlm_sprite_auditor.py`)
Скрипт відправляє сгенерований спрайт-лист на локальний вузол Jetson (`http://192.168.68.68:11434` / `gemma4:12b` або `gemma3:12b`):
* Промпт містить критерії канону Київнаукфільм (характерний козацький профіль, відсутність тривимірного пластикового шуму, чіткий контур, виразність).
* Відповідь парситься на JSON: `{"score": 1..10, "verdict": "PASS"|"FAIL", "issues": [...]}`.
* Якщо вердикт `FAIL` (оцінка < 7) — скрипт повертає помилку та виводить зауваження для корекції параметрів матеріалу чи поз.

*Критерій приймання:* Валідатор успішно взаємодіє з Jetson API та виставляє об'єктивну оцінку за менш ніж 4 секунди.

---

### SWR-003-07: Автоматичний тест цілісності (`test/test_sprite_pipeline.gd`)
До тестового стенду `tools/run_tests.sh` додається перевірка:
1. Валідність згенерованих файлів `SpriteFrames`.
2. Відсутність нульових розмірів кадрів.
3. Проходження повної перевірки 11/11 тестів гри.

*Критерій приймання:* `tools/run_tests.sh` виводить `PASS test_sprite_pipeline`.
