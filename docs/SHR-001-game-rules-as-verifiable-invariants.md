# SHR-001: Правила гри як перевірювані інваріанти

- **Проєкт:** «Geek Jack: Джура» (`~/geek-jack`)
- **Статус:** DRAFT
- **Дата:** 2026-10-24
- **Походження:** власник проєкту; методологія з `~/vida` (SHR → SWR → ADR → Task → Code → Test)

## Потреба зацікавленої сторони

Дизайн-документи ([`LEVEL_PROGRESSION_STORY_8PLUS.md`](LEVEL_PROGRESSION_STORY_8PLUS.md), [`MEMO_FOLKLORE_CHARACTERS.md`](MEMO_FOLKLORE_CHARACTERS.md), [`MEMO_BOXING_SUPERHEROES_PROGRESSION.md`](MEMO_BOXING_SUPERHEROES_PROGRESSION.md)) задають правила гри для дітей 8+ словами. Власник хоче, щоб правила не розходилися з кодом: порушення має виявляти автоматична перевірка, а не гравець.

## Правила, що мають стати інваріантами

| № | Правило | Джерело |
|---|---|---|
| I-1 | Кожен рівень серії вводить щонайменше одного нового NPC (ворога чи союзника) і не більше одного нового типу ворога (рішення власника 2026-10-24: варіант «а», потім «кожен наступний рівень вводить нового NPC») | `LEVEL_PROGRESSION…` |

| I-5 | «Тверда стеля» кам'яних склепінь працює однаково для всіх рівнів, де вона є | `LEVEL_PROGRESSION…` |

## Обмеження та ризики (рецензент)

1. **Реальні особи.** Прототипами Джури названо Кличків і Усика, а «Dr. Steelhammer» та «Dr. Ironfist» є їхніми псевдонімами. Перед публічним випуском потрібне рішення власника: згода правовласників або узагальнення образів.
2. **Образ ворога.** «Москалі з багнетами» в дитячій грі: перевірити формулювання й вікове сприйняття (тон, а не заборона).
3. **Інваріант не замінює плейтест.** Прохідність за графом не гарантує, що рівень цікавий; потрібні живі діти.

## Критерій приймання потреби

Кожне правило I-1…I-7 має автоматичну перевірку, що запускається однією командою і падає при порушенні (див. [`SWR-001`](SWR-001-executable-rule-checks.md)).
