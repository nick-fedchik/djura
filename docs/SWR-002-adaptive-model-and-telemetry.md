# SWR-002: Адаптивна модель, телеметрія й оцінка складності

- **Статус:** DRAFT
- **Дата:** 2026-10-24
- **Трасується до:** [`SHR-003`](SHR-003-adaptive-difficulty-and-independent-telemetry.md) · **Рішення:** [`ADR-002`](ADR-002-bayesian-flow-adaptation.md)

### SWR-002-01. Телеметрія (A-1, A-6)
`scripts/telemetry.gd` пише події схеми v1 у `user://telemetry/events.jsonl` (поворот файлу за розміром). Події: `session_start`, `level_start`, `hit`, `bomb`, `enemy_defeated`, `level_end`, `abandon`, `session_end`. Ключі лише з білого списку; персональних даних немає; ідентифікатор гравця випадковий і локальний; у headless-режимі не пишеться. Приймання: тест схеми й заборони зайвих ключів.

### SWR-002-02. Модель гравця (A-2, A-3)
`scripts/player_model.gd`: вміння θ ~ N(μ, σ²) у логітах; модель успіху `p = σ(θ − b)`, `b = log2(K) + зсув_рівня`; байєсове оновлення (щільність, що припускається, + шум процесу для навчання); цільова ймовірність за профілем (вік, досвід); складність наступного рівня з обмеженням швидкості зміни (slew) і межами. Приймання: симуляція синтетичних гравців сходиться до цілі, не розгойдується, K монотонний за вмінням.

### SWR-002-03. Розвідка інтересу (A-3)
Багаторукий бандит (Thompson sampling, Beta-постеріори) над зсувами цілі {−0,5; 0; +0,5} логіт; винагорода — ознака «потоку» (не нудно й не фрустровано, завершення рівня, продовження сесії). Приймання: у симуляції бандит віддає перевагу руці, оптимальній для синтетичного гравця.

### SWR-002-04. Виявлення нудьги й фрустрації (A-3)
Детерміновані індекси за часом, ударами й якістю; нудьга піднімає ціль складності, фрустрація знижує; обидва обмежені slew.

### SWR-002-05. Захисні межі (A-7)
`K` у `[K_MIN, K_MAX]` і не вище за стелю вікової групи; крок між рівнями ≤ `SLEW`; не більше двох підвищень поспіль за фрустрації. Приймання: властивісні тести на випадкових послідовностях.

### SWR-002-06. Статична оцінка складності рівня (A-4)
`scripts/level_difficulty.gd`: показники геометрії (висота кроків відносно стрибка, ширина платформ, розкид ядер) і складу; зсув рівня в логітах з нульовою середньою. Приймання: детермінована таблиця для 5 етапів.

### SWR-002-07. Емпірична оцінка (A-4)
`tools/analyze_telemetry.py`: відновлює рівні/гравців із телеметрії (ітераційна калібровка Раша), дає звіт: воронка завершення, помилка прогнозу моделі, прапорці «надто легко/важко». Приймання: тест на синтетичних даних відновлює відомі складності рівнів.

### SWR-002-08. Дорадча оцінка Ollama (A-5)
`tools/ollama_review.py`: передає у модель лише агрегований звіт, вимагає JSON за схемою; `tools/tuning_validator.py` (білий список параметрів і межі) відхиляє все зайве; результат — файл пропозицій для людини. Приймання: тест валідатора на коректних і зловмисних відповідях; модель не викликається під час гри.
