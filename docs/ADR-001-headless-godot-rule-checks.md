# ADR-001: Перевірки правил у headless-режимі Godot

- **Статус:** PROPOSED
- **Дата:** 2026-10-24
- **Трасується до:** [`SWR-001`](SWR-001-executable-rule-checks.md), [`SHR-001`](SHR-001-game-rules-as-verifiable-invariants.md)

## Контекст
Тести вже існують: `test/test_levels.gd`, `test/test_jump_to_top_beam.gd` (клас `SceneTree`, запуск через `godot`). Правила потрібно перевіряти без ручного грання.

## Рішення
Перевірки пишуться на GDScript як скрипти `SceneTree` у `test/`, запускаються `godot --headless`. Прохідність обчислюється аналітично за константами `player.gd`, а не симуляцією кожного кадру. Геометрія персонажів виноситься з `_draw()` у чисті функції (точки ріжків, овал голови), щоб її можна було перевірити без рендеру.

## Альтернативи
1. **Зовнішній Python-перевірник.** Дублює константи й розходиться з кодом. Відхилено.
2. **Лише ручний плейтест.** Не ловить регресії. Відхилено як єдиний метод.
3. **Симуляція боту в Godot (кадр за кадром).** Точніша, але повільна й нестабільна. Відкладено; може доповнити аналітичну перевірку (див. SHR-002 для ідей).

## Наслідки
- (+) Правила й код не розходяться непомітно.
- (+) Виправлення ріжків супроводжується тестом-запобіжником.
- (−) Рефакторинг `_draw()` у `enemy.gd` для винесення геометрії.
- (−) Аналітична прохідність консервативна: можливі хибнопозитивні відмови на «хитрих» стрибках.
